# 02 知识图谱基础

上一节讲了普通 RAG：它主要从文本 chunk 中找相似内容。GraphRAG 的变化是：不仅保存文本，还把文本里的对象和关系整理成图。本节先理解知识图谱。

---

## 本节学习目标

学完本节后，你应该能：

- 解释什么是实体、关系、属性。
- 看懂三元组。
- 理解节点和边。
- 知道知识图谱和普通表格数据的区别。
- 能把一段文本手动拆成实体和关系。

---

## 核心概念解释

### 1. 实体

实体就是文本里重要的“东西”。

可以是：

```text
人：张三、李四
组织：某某公司、研发部
项目：项目 A、智能客服系统
文档：合同 B、需求文档 C
概念：GraphRAG、向量检索、权限控制
代码对象：UserService、login 函数、OrderController
```

### 2. 关系

关系表示两个实体之间有什么联系。

例如：

```text
张三 负责 项目 A
项目 A 使用 FastAPI
合同 B 约束 供应商 C
login 函数 调用 UserRepository
```

### 3. 属性

属性是实体或关系上的补充信息。

例如实体：

```text
实体：合同 B
属性：签署日期 = 2026-01-01
属性：金额 = 100 万
属性：状态 = 生效中
```

例如关系：

```text
关系：张三 负责 项目 A
属性：开始时间 = 2026-03-01
属性：角色 = 后端负责人
```

### 4. 三元组

三元组是知识图谱里最常见的表达方式：

```text
主语 -> 谓语 -> 宾语
```

例如：

```text
张三 -> 负责 -> 项目 A
项目 A -> 使用 -> FastAPI
合同 B -> 属于 -> 公司 C
```

### 5. 节点和边

如果用图来表示：

```text
实体 = 节点
关系 = 边
```

例如：

```text
[张三] --负责--> [项目 A]
[项目 A] --使用--> [FastAPI]
```

---

## 通俗理解

普通文档像一篇文章，知识图谱像一张关系网。

文章里的信息是线性的：

```text
第一段 -> 第二段 -> 第三段
```

图谱里的信息是网络状的：

```text
人 -> 项目 -> 合同 -> 公司 -> 风险条款
```

如果你问：

```text
“张三负责的项目涉及哪些合同风险？”
```

普通 RAG 可能要碰巧找到相关 chunk。  
知识图谱可以沿着关系走：

```text
张三 -> 负责 -> 项目 A -> 关联 -> 合同 B -> 包含 -> 风险条款
```

这就是图的优势。

## 技术流程图

从文本到图：

```text
原始文本：
张三负责项目 A。项目 A 使用 FastAPI，并关联合同 B。

实体识别：
张三、项目 A、FastAPI、合同 B

关系抽取：
张三 -> 负责 -> 项目 A
项目 A -> 使用 -> FastAPI
项目 A -> 关联 -> 合同 B

图结构：
[张三] --负责--> [项目 A] --使用--> [FastAPI]
                      |
                    关联
                      |
                   [合同 B]
```

## 关键代码/伪代码示例

```python
text = "张三负责项目 A。项目 A 使用 FastAPI，并关联合同 B。"

entities = [
    {"name": "张三", "type": "Person"},
    {"name": "项目 A", "type": "Project"},
    {"name": "FastAPI", "type": "Technology"},
    {"name": "合同 B", "type": "Contract"},
]

relations = [
    {"source": "张三", "target": "项目 A", "type": "负责"},
    {"source": "项目 A", "target": "FastAPI", "type": "使用"},
    {"source": "项目 A", "target": "合同 B", "type": "关联"},
]

graph.add_nodes(entities)
graph.add_edges(relations)
```

这段伪代码表达的是：

```text
先抽实体。
再抽关系。
最后把实体和关系放进图里。
```

## 实际项目中怎么用

### 文档问答

实体可能是：

```text
制度名称、部门、流程、审批人、金额、时间
```

关系可能是：

```text
部门 -> 负责 -> 流程
流程 -> 需要 -> 审批人
报销 -> 限制 -> 金额
```

### 合同审查

实体可能是：

```text
甲方、乙方、合同、付款条款、违约责任、终止条件
```

关系可能是：

```text
甲方 -> 支付 -> 款项
乙方 -> 承担 -> 交付义务
合同 -> 包含 -> 违约责任
```

### 代码知识库

实体可能是：

```text
类、函数、模块、接口、数据库表
```

关系可能是：

```text
函数 A -> 调用 -> 函数 B
Service -> 依赖 -> Repository
接口 -> 读写 -> 数据表
```

---

## 容易混淆的点

### 1. 实体不是所有名词

不是文本里每个名词都值得放进图。  
实体应该是对检索和问答有价值的对象。

### 2. 关系不是普通句子

关系应该表达两个实体之间的明确联系。  
例如“负责”“属于”“调用”“依赖”“包含”。

### 3. 图谱不是必须非常复杂

新手项目可以先做简单图：

```text
实体表 + 关系表
```

不一定一开始就上复杂图数据库。

### 4. 知识图谱不等于 GraphRAG

知识图谱是知识组织方式。  
GraphRAG 是把图谱用于 RAG 检索和生成的流程。
