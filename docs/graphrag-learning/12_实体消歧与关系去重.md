# 12 实体消歧与关系去重

如果说 GraphRAG 的入门难点是“怎么抽实体关系”，那进阶难点就是“抽出来以后怎么清洗”。  
这一节专门讲实体消歧和关系去重。

---

## 本节学习目标

学完本节后，你应该能：

- 理解什么是实体消歧。
- 理解什么是实体标准化。
- 知道同名不同物、同物不同名为什么会让图变乱。
- 理解关系去重和关系置信度。
- 能设计一个新手可实现的清洗流程。

---

## 核心概念解释

### 1. 实体标准化

实体标准化是把实体名字处理成更统一的形式。

例如：

```text
 FastAPI
fastapi
FastAPI 框架
```

可能都标准化为：

```text
FastAPI
```

标准化常用规则：

```text
去空格
统一大小写
去掉无意义后缀
统一简称
```

### 2. 实体消歧

实体消歧是判断两个实体到底是不是同一个东西。

两种常见情况：

```text
同物不同名：FastAPI、FastAPI 框架、fastapi
同名不同物：苹果公司、苹果水果
```

GraphRAG 里更麻烦的是：

```text
同一个角色可能被叫全名、外号、身份称呼。
同一个系统可能被叫中文名、英文名、简称。
```

### 3. Canonical Entity

Canonical Entity 可以理解为“标准实体”。

例如：

```text
原始实体：
叶逍遥
叶先生
主角

标准实体：
叶逍遥
```

后续图里尽量只用标准实体作为节点。

### 4. 关系去重

关系去重是把重复关系合并。

例如从多个 chunk 抽到：

```text
叶逍遥 -> 保护 -> 叶婷
叶逍遥 -> 保护 -> 叶婷
叶逍遥 -> 守护 -> 叶婷
```

可以合并为一条主关系：

```text
叶逍遥 -> 保护/守护 -> 叶婷
```

同时保留多个来源 chunk。

### 5. 置信度

置信度表示这条实体或关系有多可信。

例如：

```text
0.95：多处文本明确支持
0.60：只有一次模糊提到
0.30：LLM 推测成分较强
```

新手项目可以先不用复杂模型打分，但建议预留字段。

---

## 通俗理解

如果不做实体消歧，你的图会像通讯录乱套：

```text
张三
张三同学
三哥
销售部张三
```

明明可能是同一个人，却变成了四个节点。

如果不做关系去重，你的图会像反复抄了很多遍：

```text
张三负责项目 A
张三负责项目 A
张三负责项目 A
```

结果图看起来很大，但很多都是重复噪声。

---

## 技术流程图

实体清洗流程：

```text
原始实体
-> 名称标准化
-> 按类型分组
-> 相似名称聚类
-> 使用上下文判断是否同一实体
-> 生成 canonical entity
-> 建立 alias 映射
```

关系清洗流程：

```text
原始关系
-> 替换 source / target 为标准实体
-> 关系类型标准化
-> 合并重复关系
-> 合并 source_chunk_ids
-> 计算或设置 confidence
-> 保存 cleaned relations
```

## 关键代码/伪代码示例

### 1. 实体标准化

```python
def normalize_name(name: str) -> str:
    name = name.strip()
    name = name.replace(" 框架", "")
    name = name.replace("系统", "")
    return name.lower()
```

### 2. 简单实体合并

```python
def merge_entities(entities: list[dict]) -> tuple[list[dict], dict]:
    canonical_map = {}
    merged = {}

    for entity in entities:
        key = (entity["type"], normalize_name(entity["name"]))

        if key not in merged:
            canonical_id = create_id()
            merged[key] = {
                "id": canonical_id,
                "name": entity["name"],
                "type": entity["type"],
                "aliases": [entity["name"]],
                "descriptions": [entity.get("description", "")],
            }
        else:
            merged[key]["aliases"].append(entity["name"])
            merged[key]["descriptions"].append(entity.get("description", ""))

        canonical_map[entity["name"]] = merged[key]["id"]

    return list(merged.values()), canonical_map
```

### 3. 关系去重

```python
def deduplicate_relations(relations: list[dict], canonical_map: dict) -> list[dict]:
    grouped = {}

    for relation in relations:
        source_id = canonical_map.get(relation["source"])
        target_id = canonical_map.get(relation["target"])
        relation_type = normalize_relation_type(relation["type"])

        key = (source_id, relation_type, target_id)

        if key not in grouped:
            grouped[key] = {
                "source_id": source_id,
                "target_id": target_id,
                "type": relation_type,
                "descriptions": [],
                "source_chunk_ids": set(),
                "confidence": 0.6,
            }

        grouped[key]["descriptions"].append(relation.get("description", ""))
        grouped[key]["source_chunk_ids"].add(relation["source_chunk_id"])

    return [
        {
            **relation,
            "source_chunk_ids": list(relation["source_chunk_ids"]),
            "confidence": min(0.95, 0.5 + 0.1 * len(relation["source_chunk_ids"])),
        }
        for relation in grouped.values()
    ]
```

## 实际项目中怎么用

### 企业知识库

常见别名：

```text
人力资源部 / HR / 人事部
财务部 / 财务中心
报销流程 / 费用报销流程
```

可以维护一张人工 alias 表：

```text
alias_name -> canonical_name
HR -> 人力资源部
人事部 -> 人力资源部
```

### 合同审查

常见别名：

```text
甲方 / 委托方 / 买方
乙方 / 服务方 / 供应商
```

要注意：

```text
不同合同里的甲方不一定是同一个公司。
```

所以实体消歧要结合文档上下文。

### 代码知识库

常见别名：

```text
UserService
user_service.py
用户服务
```

代码场景里可以结合路径：

```text
app/services/user_service.py::UserService
```

这样比只用名字更准确。

---

## 容易混淆的点

### 1. 名字一样不代表同一个实体

合同里的“甲方”在不同合同中可能指不同公司。

### 2. 名字不同不代表不同实体

“HR”“人事部”“人力资源部”可能是一个部门。

### 3. 不要只靠字符串相似度

字符串相似度只能做初筛。  
最终最好结合实体类型、上下文、来源文档判断。

### 4. 不要丢掉 alias

alias 对后续查询很重要。  
用户可能问“HR”，但图里标准实体叫“人力资源部”。

### 5. 合并关系时不要丢来源

重复关系可以合并，但来源 chunk 要保留。  
否则回答时没证据。
