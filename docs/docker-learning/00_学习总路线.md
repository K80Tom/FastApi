# 00 学习总路线

## 1. 这一节要解决什么问题

这一节帮你看清 Docker 从"是什么、为什么用"到"安装、镜像、容器、Dockerfile、Compose、生产实践"的完整路线，知道先学什么、后学什么、每天怎么安排，以及遇到问题怎么定位。

## 2. 基础概念解释

### Docker

通俗解释：Docker 像一个集装箱标准，把你的应用和它需要的所有东西（代码、运行环境、依赖、配置）打包进一个"箱子"，这个箱子在任何支持 Docker 的机器上都能以完全相同的方式运行。

技术解释：Docker 是一个基于 Linux 容器（LXC/cgroups/namespaces）技术的开源容器化平台，提供镜像构建、容器运行、仓库分发等能力，是目前最主流的容器化工具。

例子：你在本地用 Python 3.11 + FastAPI 写了一个服务，用 Docker 打包后，无论是同事的 Mac、测试服务器还是云主机，都能用完全相同的环境跑起来，不需要手动安装任何依赖。

### 容器

通俗解释：容器是一个隔离的"小盒子"，里面跑着你的应用，和宿主机及其他容器互不干扰，但共享同一个操作系统内核。

技术解释：容器是镜像的运行实例，通过 Linux namespaces 实现进程/网络/文件系统隔离，通过 cgroups 限制 CPU/内存资源使用，启动速度快（毫秒级），占用资源少。

例子：你可以在同一台机器上同时跑 5 个不同版本的 Node.js 服务，每个在自己的容器里，互不影响。

### 镜像

通俗解释：镜像是容器的"模板"，就像安装 Windows 用的 ISO 文件，镜像本身不能直接修改，用它可以启动很多个一样的容器。

技术解释：Docker 镜像是一个只读的分层文件系统，每一层代表 Dockerfile 中的一条指令，多个镜像可以共享底层，节省存储空间。

例子：你从 Docker Hub 拉取了一个 `python:3.11-slim` 镜像，这是官方维护的，你基于它再加一层（安装你的依赖），就成了你自己的镜像。

## 3. 为什么要学这个

如果你不懂 Docker，你只能在自己的机器上跑项目，换一台机器就要重新配置环境，出现"在我这里能跑"的问题。掌握 Docker 后，你能把项目打包成随处可运行的镜像，能用 Compose 一键启动多个服务，能在面试中流利讲清楚容器化的价值。

### 4.6 学习方法建议

```text
每次操作前：先 docker ps -a 看清楚当前有哪些容器
每次改 Dockerfile：先想清楚每一层做了什么，再构建
遇到不认识的报错：先复制报错关键词，查 14_常见报错
容器跑不起来：docker logs <容器名> 是第一步
想进容器里看看：docker exec -it <容器名> /bin/bash 或 /bin/sh
不知道镜像有什么：docker inspect <镜像名> 查详细信息
```

注意事项：不要养成"容器挂了就删掉重建"的习惯，先用 logs 查清楚原因，否则每次都是玄学排查。

## 8. 常见误区

1. 误区：Docker 就是虚拟机。  
   解释：容器共享宿主机内核，启动快、资源占用小；虚拟机有完整独立的 OS，隔离性更强但更重。

2. 误区：Docker 只有运维才需要学。  
   解释：开发、测试、运维都需要 Docker。开发用它统一环境，测试用它跑 CI，运维用它部署服务。

3. 误区：会了 docker run 就会 Docker 了。  
   解释：命令只是入口，难的是 Dockerfile 的优化、网络通信模型、数据持久化策略、Compose 编排设计。

4. 误区：容器里的数据会自动保存。  
   解释：容器删了，里面的数据默认就没了。必须用 Volume 才能持久化，这是新手最常踩的坑之一。

## 9. 本节总结

Docker 学习要从"理解为什么需要容器"开始，再到"能操作容器"，再到"能自己构建镜像"，最后到"多服务编排和生产实践"。7 天计划适合建立第一印象，14 天计划适合系统掌握，30 天计划适合把容器化融入真实项目。最重要的原则：每次出问题先看日志，养成用 `docker logs` 排查的习惯。
