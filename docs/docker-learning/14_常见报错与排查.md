# 14 常见报错与排查

## 1. 这一节要解决什么问题

收录 Docker 使用中最常见的报错，帮你快速定位原因和解决方案。遇到问题时先来这里找，有明确方向再深入排查。

## 2. 排查通用思路

```text
容器跑不起来？
  → docker logs 容器名        （看启动日志，99% 能找到原因）
  → docker inspect 容器名     （看容器详细配置，找异常）

容器在跑但服务访问不到？
  → docker ps                 （确认端口映射是否正确）
  → docker exec -it 容器名 sh （进容器里检查服务是否真的在跑）
  → curl localhost:容器内端口 （在容器里测，排查是容器内问题还是网络映射问题）

服务间访问不通？
  → docker network inspect 网络名   （确认容器都在同一网络）
  → docker exec 容器 ping 目标容器名 （测试 DNS 和连通性）

镜像拉不下来？
  → 检查网络和加速器配置
  → docker pull 完整镜像地址（含仓库前缀）
```

## 3. 常见报错速查

### 3.1 Docker Daemon 相关

**报错：`Cannot connect to the Docker daemon at unix:///var/run/docker.sock`**
```
原因：Docker Daemon 没有运行
解决：
  - Windows/Mac：打开 Docker Desktop 等它启动完成
  - Linux：sudo systemctl start docker
  - 验证：docker info
```

**报错：`permission denied while trying to connect to the Docker daemon socket`**
```
原因：当前用户没有权限访问 docker socket
解决（Linux）：
  sudo usermod -aG docker $USER
  newgrp docker    # 或者重新登录
```

### 3.2 镜像拉取相关

**报错：`Error response from daemon: pull access denied` 或 `repository does not exist`**
```
原因一：镜像名写错了，Docker Hub 上没有这个镜像
解决：在 hub.docker.com 搜索正确的镜像名

原因二：私有镜像没登录
解决：docker login [仓库地址]
```

**报错：`context deadline exceeded` 或 `dial tcp: lookup registry-1.docker.io: no such host`**
```
原因：网络问题，无法连接到 Docker Hub
解决：
  1. 检查网络连接
  2. 配置镜像加速器（见 02_安装 节）
  3. 检查 Docker Desktop 是否在运行
```

**报错：`no matching manifest for linux/amd64 in the manifest list entries`**
```
原因：镜像没有提供当前架构的版本（常见于 Apple M1/M2 访问 amd64-only 镜像）
解决：
  方案一：docker pull --platform linux/amd64 镜像名（强制拉 amd64，有性能损失）
  方案二：找有 arm64 版本的镜像
```

### 3.3 容器启动相关

**报错：`Error: bind: address already in use`（端口冲突）**
```
原因：宿主机的指定端口已被其他程序占用
解决：
  - 换一个宿主机端口：-p 8081:80 而不是 -p 8080:80
  - 找出占用进程（Windows: netstat -ano | findstr 8080）（Linux/Mac: lsof -i :8080）
  - 停掉占用的程序
```

**报错：容器启动后立刻退出（`Exited (1)` 或 `Exited (0)`）**
```
排查步骤：
  docker logs 容器名    # 查看退出前的输出

常见原因：
  - Exited (0)：程序正常执行完毕退出（hello-world 就是这样），不是错误
  - 程序找不到入口文件（COPY 路径写错）
  - CMD 写错（程序不存在或参数不对）
  - 缺少必要环境变量
  - 依赖的服务未就绪（数据库没起来）
```

**报错：`OCI runtime exec failed: exec: "bash": executable file not found in $PATH`**
```
原因：镜像里没有 bash（alpine 镜像只有 sh）
解决：
  docker exec -it 容器名 sh    # 用 sh 替代 bash
  docker exec -it 容器名 /bin/sh
```

### 3.4 Dockerfile 构建相关

**报错：`COPY failed: file not found in build context`**
```
原因：COPY 指令里的源路径在构建上下文（build context）里不存在
排查：
  - 确认文件确实存在于 Dockerfile 所在目录（或指定的构建上下文目录）
  - 检查 .dockerignore 是否把这个文件排除了
  - COPY 路径是相对于构建上下文的，不是相对于 Dockerfile 的位置
```

**报错：`RUN apt-get install` 失败，找不到包**
```
原因：没有先 apt-get update，包列表过期
解决：
  RUN apt-get update && apt-get install -y 包名
  # update 和 install 必须在同一个 RUN 里！
  # 如果分开，第二次 build 用了 update 的缓存但包列表可能过期
```

**报错：`pip install` 超时或失败**
```
解决：
  # 使用国内 pip 镜像
  RUN pip install -r requirements.txt \
      -i https://mirrors.aliyun.com/pypi/simple/ \
      --trusted-host mirrors.aliyun.com
```

### 3.5 Volume 相关

**问题：挂载 Volume 后容器内文件权限报错（Permission denied）**
```
原因：容器内进程用非 root 用户运行，但挂载的 volume 属主是 root
解决方案：
  方案一：Dockerfile 里 RUN chown -R 用户:用户 /app/data
  方案二：docker run -u 0（以 root 运行，不推荐）
  方案三：确保宿主机目录的权限正确（chmod 777 /宿主机路径，开发环境可用）
```

**问题：Bind Mount 挂载后容器内目录是空的**
```
原因：宿主机路径写错，或 Windows 路径格式问题
排查：
  docker inspect 容器名 | grep -A 10 Mounts   # 查看实际挂载了什么
Windows 路径格式：
  -v "C:\Users\name\project:/app"       # 双引号包裹路径
  -v //c/Users/name/project:/app        # Git Bash 格式
```

### 3.6 网络相关

**报错：`dial tcp: connect: connection refused`（容器内服务无法访问）**
```
排查步骤：
  1. 确认服务在容器内真的在监听：docker exec -it 容器名 netstat -tlnp
  2. 确认监听地址是 0.0.0.0，不是 127.0.0.1
     （127.0.0.1 只接受本机请求，容器外无法访问）
  3. 确认端口映射正确：docker port 容器名
```

**报错：容器间访问不通（`ping: bad address '容器名'`）**
```
原因：两个容器不在同一个自定义网络里
解决：
  1. 创建自定义网络：docker network create mynet
  2. 两个容器都加入：docker run --network mynet ...
  3. 注意：默认 bridge 网络不支持用容器名访问！
```

### 3.7 Docker Compose 相关

**报错：`Service "xxx" failed to build: Dockerfile parse error`**
```
原因：Dockerfile 语法错误
解决：仔细阅读报错后的行号，检查 Dockerfile 里那一行的语法
```

**问题：`docker compose up` 后 API 无法连接数据库**
```
排查：
  1. docker compose ps          # 检查 db 是否正常运行
  2. docker compose logs db     # 看数据库日志有没有报错
  3. 确认 depends_on condition: service_healthy（见 11 节）
  4. 确认连接字符串里的主机名是 compose 的服务名（如 db），不是 localhost
```

## 4. 常用排查命令

```bash
# 容器跑不起来：查日志
docker logs 容器名
docker logs --tail 100 容器名     # 只看最后 100 行
docker compose logs 服务名

# 进入容器内部检查
docker exec -it 容器名 sh

# 查看容器详细信息（挂载、网络、环境变量等）
docker inspect 容器名

# 查看容器资源使用
docker stats 容器名

# 查看网络里有哪些容器
docker network inspect 网络名

# 查看实际占用端口
docker port 容器名
```

## 5. 本节总结

出问题时优先用 `docker logs 容器名` 查日志，90% 的问题在日志里有答案。进不去服务用 `docker exec -it 容器名 sh` 进容器内部排查。网络不通先确认容器是否在同一自定义网络里。本节是速查手册，遇到问题直接按关键词找对应部分。
