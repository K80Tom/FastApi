# 12 镜像仓库与分发

## 1. 这一节要解决什么问题

帮你学会把自己构建的镜像推送到远端仓库（Docker Hub 或私有仓库），让团队成员或服务器都能拉取使用，实现镜像的分发和版本管理。

## 2. 基础概念解释

### Registry（镜像仓库）

通俗解释：Registry 就是存放 Docker 镜像的"代码托管平台"，就像 GitHub 存代码，Docker Hub 存镜像。你把镜像 push 上去，别人就能 pull 下来。

技术解释：Registry 是实现了 OCI Distribution Specification 的服务，提供镜像的 push/pull API。镜像以层（layer）为单位存储，相同的层只存一份。

## 3. 关键知识点

### 3.1 Docker Hub 使用

```bash
# 第一步：注册 Docker Hub 账号（hub.docker.com）

# 第二步：本地登录
docker login
# 输入 Docker Hub 用户名和密码
# 或者用 token（推荐）：
# docker login -u 用户名 --password-stdin <<< "你的token"

# 第三步：给镜像打正确的标签
# 格式：用户名/镜像名:标签
docker tag myapp:latest yourusername/myapp:latest
docker tag myapp:latest yourusername/myapp:v1.0.0

# 第四步：推送镜像
docker push yourusername/myapp:latest
docker push yourusername/myapp:v1.0.0

# 推送所有标签
docker push yourusername/myapp --all-tags

# 第五步：验证（在浏览器 hub.docker.com 查看，或者拉取测试）
docker pull yourusername/myapp:v1.0.0
```

### 3.2 镜像标签规范

推荐的标签策略：

```bash
# 语义化版本（Semantic Versioning）
docker tag myapp:latest myuser/myapp:1.2.3
docker tag myapp:latest myuser/myapp:1.2       # 次版本（向后兼容的小版本）
docker tag myapp:latest myuser/myapp:1         # 主版本
docker tag myapp:latest myuser/myapp:latest    # 最新稳定版

# 结合 git commit hash（方便追溯）
GIT_SHA=$(git rev-parse --short HEAD)
docker tag myapp:latest myuser/myapp:${GIT_SHA}

# 结合构建日期
docker tag myapp:latest myuser/myapp:$(date +%Y%m%d)

# 生产环境严禁只用 latest，因为不知道具体是哪个版本
# 推荐：同时打 latest 和具体版本号标签
```

### 3.3 GitHub Container Registry（GHCR）

GitHub 提供了免费的镜像仓库，和代码仓库绑定，推荐开源项目使用。

```bash
# 用 GitHub Personal Access Token 登录
echo $GITHUB_TOKEN | docker login ghcr.io -u 你的github用户名 --password-stdin

# 镜像命名格式：ghcr.io/用户名/镜像名:标签
docker tag myapp:latest ghcr.io/yourusername/myapp:v1.0.0
docker push ghcr.io/yourusername/myapp:v1.0.0
```

### 3.4 阿里云容器镜像服务（国内推荐）

```bash
# 阿里云提供免费私有镜像仓库（100 个）
# 控制台：https://cr.console.aliyun.com/

# 登录（阿里云会给你专属登录命令）
docker login --username=你的账号 registry.cn-hangzhou.aliyuncs.com

# 标记和推送
docker tag myapp:latest registry.cn-hangzhou.aliyuncs.com/你的命名空间/myapp:v1.0.0
docker push registry.cn-hangzhou.aliyuncs.com/你的命名空间/myapp:v1.0.0
```

### 3.5 搭建私有 Registry

适合内部使用、不想把镜像放公开仓库的场景：

```yaml
# docker-compose.yml（运行私有 registry）
services:
  registry:
    image: registry:2
    ports:
      - "5000:5000"
    volumes:
      - registry-data:/var/lib/registry
    restart: unless-stopped

volumes:
  registry-data:
```

```bash
# 启动私有 registry
docker compose up -d

# 推送到私有 registry
docker tag myapp:latest localhost:5000/myapp:v1.0.0
docker push localhost:5000/myapp:v1.0.0

# 从私有 registry 拉取
docker pull localhost:5000/myapp:v1.0.0

# 列出仓库里的所有镜像
curl http://localhost:5000/v2/_catalog

# 列出某个镜像的所有标签
curl http://localhost:5000/v2/myapp/tags/list
```

注意事项：默认 Registry 没有认证，只适合内网或开发环境。生产环境要配置 TLS 和基本认证，或者用 Harbor 替代。

### 3.6 在 CI/CD 中自动推送镜像

GitHub Actions 示例：

```yaml
# .github/workflows/docker-publish.yml
name: Build and Push Docker Image

on:
  push:
    tags:
      - 'v*'                    # 打 tag 时触发

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_TOKEN }}

      - name: Build and push
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: |
            yourusername/myapp:latest
            yourusername/myapp:${{ github.ref_name }}
```

### 3.7 镜像导出和导入（离线分发）

没有网络的环境可以用文件分发镜像：

```bash
# 导出镜像为 tar 文件
docker save myapp:v1.0.0 -o myapp-v1.0.0.tar

# 导出多个镜像
docker save myapp:v1.0.0 nginx:alpine -o images.tar

# 导入镜像（在另一台机器上）
docker load -i myapp-v1.0.0.tar
```

## 4. 和前后知识的关系

镜像分发是 CI/CD 流水线的关键环节，`13_多阶段构建` 确保推上去的镜像体积小、构建快，`16_生产实践` 里的部署流程依赖镜像仓库。

## 5. 实战任务

1. 注册 Docker Hub 账号，用 `docker login` 登录。
2. 构建一个自己的镜像，用 `yourusername/myapp:v1.0.0` 格式打标签。
3. `docker push` 推送到 Docker Hub，在网页上验证能看到镜像。
4. `docker rmi` 删除本地镜像，再 `docker pull yourusername/myapp:v1.0.0` 拉取验证。

## 6. 常见误区

1. 误区：push 之前不需要登录，push 会提示登录。  
   解释：不登录会直接报 `denied: requested access to the resource is denied` 错误，看起来像权限问题。先 `docker login`。

2. 误区：push latest 一个标签就够了。  
   解释：只有 latest 的镜像无法追溯版本，出问题不知道回滚到哪个版本。始终同时打具体版本标签。

## 7. 本节总结

镜像分发的核心流程：`docker tag` 打标签（用户名/镜像名:版本）→ `docker login` 登录仓库 → `docker push` 推送。Docker Hub 免费但有速率限制，阿里云适合国内私有镜像，GHCR 适合开源项目。生产环境镜像标签要包含具体版本号，不能只用 latest。
