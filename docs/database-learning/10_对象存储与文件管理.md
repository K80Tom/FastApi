# 对象存储与文件管理

> 补充文档：理解大文件的存储方案，掌握"PG存路径+对象存储存文件"的模式

---

## 学习目标

1. 理解为什么图片/视频不能存数据库
2. 掌握对象存储的基本操作（上传/下载/presigned URL）
3. 能设计 asset_media 表和 MinIO 的配合方案

---

## 为什么需要对象存储

| 存储方式 | 问题 |
|----------|------|
| 把视频存PG的BLOB字段 | 数据库膨胀到TB级，备份慢，查询卡 |
| 存服务器本地磁盘 | 单机容量有限，服务器挂了文件丢，多实例无法共享 |
| 对象存储(MinIO/S3) | ✅ 无限扩容、分布式、CDN加速、便宜 |

## 设计模式

```
asset_media 表（PG）:
┌─────────────────────────────────────────────────┐
│ id | asset_id | media_type | storage_path        │
│ 1  | char_001 | image      | chars/001/avatar.png│
│ 2  | char_001 | video      | chars/001/demo.mp4  │
└─────────────────────────────────────────────────┘
        │
        │ storage_path 指向
        ▼
MinIO Bucket: drama-assets
├── chars/001/avatar.png    (2MB图片)
├── chars/001/demo.mp4      (50MB视频)
├── scenes/002/bg.jpg       (5MB背景图)
└── generated/task_003/out.png (AI生成结果)
```

**原则**：数据库只存路径（几十字节），实际文件在对象存储（几MB-几GB）。

## Python 操作（MinIO）

```python
from minio import Minio
from datetime import timedelta

client = Minio("localhost:9000", access_key="admin", secret_key="password", secure=False)

BUCKET = "drama-assets"

# 确保bucket存在
if not client.bucket_exists(BUCKET):
    client.make_bucket(BUCKET)

# 上传文件
def upload_asset_file(asset_id: str, file_path: str, media_type: str) -> str:
    """上传文件，返回storage_path"""
    import os
    ext = os.path.splitext(file_path)[1]
    storage_path = f"assets/{asset_id}/{media_type}{ext}"
    
    client.fput_object(BUCKET, storage_path, file_path)
    return storage_path  # 存入PG的asset_media.storage_path

# 生成临时访问URL（给前端用）
def get_presigned_url(storage_path: str, expires_hours: int = 1) -> str:
    """生成限时可访问的URL，前端直接用这个显示图片/播放视频"""
    return client.presigned_get_object(
        BUCKET, storage_path, expires=timedelta(hours=expires_hours)
    )

# 删除文件（资产删除时调用）
def delete_asset_file(storage_path: str):
    client.remove_object(BUCKET, storage_path)
```

## 在搜索结果中返回文件URL

```python
def enrich_search_results(assets: list) -> list:
    """检索完回查PG后，给媒体文件生成访问URL"""
    for asset in assets:
        if asset.get("storage_path"):
            asset["file_url"] = get_presigned_url(asset["storage_path"])
    return assets
```

## 和 Agent/RAG 的关系

1. **多模态RAG**：图片存MinIO → 用CLIP模型生成图片向量 → 存Milvus → 支持"以图搜图"
2. **Agent生成结果**：AI生成的图片/视频 → 存MinIO → PG记录路径和元数据
3. **资产预览**：前端展示搜索结果时通过presigned URL直接加载图片

---

## 高并发注意事项

| 问题 | 解决 |
|------|------|
| 大量用户同时下载同一张热门图片 | CDN缓存在边缘节点 |
| presigned URL生成频繁 | Redis缓存URL（过期前复用） |
| 大文件上传超时 | 分片上传(multipart upload) |

---

## 常见坑

1. **presigned URL过期不处理**：前端缓存了旧URL → 设置合理过期时间+前端刷新逻辑
2. **文件删了PG没删/PG删了文件没删**：两边要同步操作（事务补偿）
3. **文件命名冲突**：用 asset_id + 类型做路径，避免覆盖
4. **CORS未配置**：浏览器直接访问MinIO报跨域错误
