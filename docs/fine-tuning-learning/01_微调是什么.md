# 01 微调是什么

## 1. 这一节要解决什么问题

这一节让你真正理解大模型微调是什么、它改变模型的什么、适合解决什么问题，以及为什么它不是万能方案。

## 2. 基础概念解释

### Fine-tuning 微调

通俗解释：微调像给一个已经会开车的司机做短期专项训练，让他熟悉山路、雨天或公司接送路线，而不是从零教他方向盘和刹车。

技术解释：微调是在预训练模型基础上，用较小但更针对性的任务数据继续训练模型参数，使模型在特定任务、格式、语气或领域上表现更稳定。

例子：通用模型能回答“什么是 HTTP”，但你希望它用“面向零基础学生”的风格回答，并统一输出“概念、例子、注意事项”，就可以用类似格式的数据微调。

### 参数

通俗解释：参数像厨师脑子里的经验，盐放多少、火候多大、什么食材搭配好，都存在他的经验里。

技术解释：参数是神经网络内部的数值，训练过程会调整这些数值，从而改变模型对输入的处理方式和输出倾向。

例子：Full Fine-tuning 会改动很多参数，LoRA 只新增并训练少量参数。

### 训练

通俗解释：训练像做练习题。模型先给答案，系统拿标准答案对比，发现差距，再调整模型。

技术解释：训练是把数据输入模型，计算预测结果和目标结果之间的 loss，然后通过优化算法更新参数。

例子：用户问“请用三点解释 LoRA”，目标答案是三点结构。模型一开始输出散文式回答，训练会让它逐渐贴近目标格式。

### Loss 损失

通俗解释：loss 像考试扣分，分越高说明离标准答案越远，分越低说明越接近。

技术解释：loss 是训练时衡量模型预测和目标答案差异的数值。它通常越低越好，但不等于真实效果一定越好。

例子：训练日志里 `loss=1.2` 到 `loss=0.8`，说明模型在训练数据上更会模仿目标输出。

## 3. 为什么要学这个

如果你不理解微调的本质，就容易把所有问题都扔给微调：知识不准也微调，回答慢也微调，Prompt 不会写也微调。实际项目中，微调只是解决“模型行为和表达方式不符合需求”的一种办法，它需要数据、算力和评估成本。

## 4. 关键知识点

### 4.1 微调到底改变了什么

解释：微调改变的是模型的输出倾向。它让模型更容易按你提供的数据风格回答，而不是保证模型永远记住每条事实。

例子：你给模型 1000 条“法律咨询问答”的训练样例，它可能更像法律助手，会使用更谨慎的语气。但如果某条法规经常更新，仅靠微调可能会过期。

注意事项：把微调当成“教做题方法”和“养成回答习惯”更合适，不要把它当成数据库。

### 4.2 微调常见目标

解释：企业和个人做微调通常有五类目标。

例子：

| 目标 | 说明 | 例子 |
| --- | --- | --- |
| 风格统一 | 让回答口吻稳定 | 客服统一礼貌话术 |
| 格式稳定 | 让输出结构固定 | 总是输出 JSON |
| 任务能力 | 学会某类输入输出映射 | 文本分类、信息抽取 |
| 领域适配 | 使用领域术语和表达 | 医疗、法律、金融问答 |
| 偏好对齐 | 更符合人类偏好 | 答案更简洁、更安全 |

注意事项：如果只是让模型知道最新资料，通常优先考虑 RAG。如果是让模型“怎么答”更稳定，微调更有价值。

### 4.3 微调不是重新训练一个模型

解释：重新训练基础模型叫预训练，成本非常高。微调是在已有模型上做小范围适配。

例子：预训练像办一所大学，微调像办一门短训课。短训课不能替代大学教育，但能快速补某个岗位技能。

注意事项：初学者项目不需要训练自己的基础模型。你应该选择开源基础模型或指令模型，例如 Qwen、Llama 系列的小参数版本。

### 4.4 什么时候应该微调

解释：当你有稳定任务、足够样例、明确评估方式，并且 Prompt/RAG 很难解决时，可以考虑微调。

例子：

```text
适合微调：
1. 客服答案必须统一格式。
2. 模型要把用户输入稳定转成结构化 JSON。
3. 你有大量高质量问答样例。
4. 你希望小模型学会某个窄任务，降低推理成本。
```

注意事项：微调前先做 baseline，也就是不用微调的基线效果。否则你不知道微调到底有没有带来提升。

### 4.5 什么时候不应该微调

解释：如果问题主要是知识库更新、事实检索、少量提示词就能解决，通常不该先微调。

例子：

```text
不优先微调：
1. 公司制度每周变化。
2. 只想让模型回答时多加一句“请注意”。
3. 数据只有十几条。
4. 没有办法判断训练后效果好不好。
5. 用户问题需要引用原文出处。
```

注意事项：很多“模型不知道”的问题，其实应该用 RAG；很多“模型答得不规整”的问题，先试 Prompt；很多“模型基础能力不行”的问题，可能要换模型。

## 8. 常见误区

1. 误区：微调就是把资料灌进模型。  
   解释：模型参数不是数据库，微调不能保证准确背诵所有资料，尤其是经常变化的资料。

2. 误区：训练数据越多越好。  
   解释：脏数据、错答案、格式混乱的数据越多，模型学坏得越快。

3. 误区：微调一定比 Prompt 好。  
   解释：很多格式和语气问题可以靠 Prompt 解决，微调有额外训练和维护成本。

4. 误区：loss 越低越好。  
   解释：loss 过低可能说明模型背住训练集，真实泛化能力反而下降。

## 9. 本节总结

微调是在已有大模型基础上做专项训练，让模型在特定任务、格式、语气或领域上更稳定。它更适合学习“怎么回答”，不适合充当动态知识库。判断是否微调时，要看目标、数据、成本和评估方式。
