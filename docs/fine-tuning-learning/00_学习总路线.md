# 00 学习总路线

## 1. 这一节要解决什么问题

这一节帮你看清“大模型微调”从概念、数据、训练、评估、部署到简历表达的完整路线，知道先学什么、后学什么、每天怎么安排。

## 2. 基础概念解释

### Fine-tuning 微调

通俗解释：微调就像一个会做很多菜的大厨，你不需要重新教他切菜、开火、调味，只需要让他练一段时间“川菜”或“儿童营养餐”，让他更适合某个场景。

技术解释：Fine-tuning 是在已有大模型参数基础上，用特定任务或领域数据继续训练，让模型在某类输入上输出更符合目标风格、格式或能力的结果。

例子：原始模型能回答通用问题，但你希望它按公司客服话术回答售后问题，就可以用客服问答数据做微调。

### Pretraining 预训练

通俗解释：预训练像一个人从小学到大学读了大量书，先获得广泛知识和语言能力。

技术解释：Pretraining 是用海量文本、代码、网页等数据训练基础模型，让模型学习语言规律、常识和推理模式。

例子：Llama、Qwen、Baichuan 这类基础模型通常先经过大规模预训练。

### Post-training 后训练

通俗解释：后训练像大学毕业后再参加职场培训，学习“怎么回答更有帮助、怎么更安全、怎么按人类偏好表达”。

技术解释：Post-training 是预训练之后的一系列训练，包括 SFT、RLHF、DPO、拒答安全训练、工具调用训练等。

例子：一个基础模型预训练后能续写文本，经过后训练后才更像聊天助手。

### SFT 监督微调

通俗解释：SFT 像老师给学生看标准答案，让学生模仿“问题应该怎么答”。

技术解释：SFT 是 Supervised Fine-tuning，用成对的输入和目标输出训练模型，让模型学习指令跟随、回答格式和任务行为。

例子：数据里写着“用户问：请解释 LoRA。助手答：LoRA 是一种参数高效微调方法……”，模型就学习这种回答方式。

### LoRA 和 QLoRA

通俗解释：LoRA 像不重写整本教材，而是在教材旁边贴一叠便签，让大厨记住某个菜系的细节。QLoRA 像把原教材压缩存放，再贴便签，省空间。

技术解释：LoRA 是 Low-Rank Adaptation，只训练少量新增低秩矩阵，冻结原模型大部分参数。QLoRA 在量化后的模型上训练 LoRA，进一步降低显存占用。

例子：7B 模型全量微调可能需要很大显存，而 LoRA/QLoRA 可以让普通单卡也跑小规模实验。

## 3. 为什么要学这个

微调不是一个单点技术，而是一条工程链路：你要先判断是否真的需要微调，再准备数据，选择方法，配置参数，跑训练，读日志，评估效果，最后部署和包装项目。总路线能防止你一上来就陷入代码和报错，却不知道每一步为什么存在。

### 4.6 学习方法模板

解释：学微调要用“项目阅读法”，别只看零散教程。

例子：

```text
看教程：先看目标 -> 再看数据 -> 再看训练命令 -> 最后看原理细节
看 GitHub：README -> requirements.txt -> train.py -> config.yaml -> dataset 示例 -> eval 脚本
看代码：入口参数 -> 模型加载 -> Tokenizer -> 数据处理 -> Trainer -> 保存模型
看数据集：字段名 -> 一条样例 -> 是否多轮 -> 是否有脏数据 -> 输出是否稳定
看日志：loss 趋势 -> learning rate -> step 时间 -> 显存 -> checkpoint
记笔记：概念、代码位置、参数作用、报错、改动、结果
复盘：目标是否达成、数据哪里有问题、模型哪里变好、哪里变差
简历：背景、方法、数据量、训练配置、评估指标、部署方式、收益
面试：先讲业务问题，再讲为什么微调，最后讲结果和反思
```

注意事项：你不需要一次看懂所有源码。先抓“输入是什么、输出是什么、谁调用谁”。

选择一个你熟悉的小领域，例如“FastAPI 入门问答”“GraphRAG 学习助手”“公司内部报销制度问答”，完成下面三件事：

3. 写出你希望模型训练后变好的 3 个方面，例如“回答格式更稳定”“术语解释更适合新手”“拒绝回答无关问题”。

## 7. 检查自己是否学会

1. 你能不能用做菜或培训的类比解释微调？
2. 微调和预训练最大的成本差异是什么？
3. 为什么有些项目更适合 RAG，而不是微调？
4. LoRA 为什么适合初学者做实验？
5. 为什么数据质量往往比训练轮数更重要？
6. 训练完成后为什么必须评估，而不是只看 loss？
7. 部署微调模型时，为什么要考虑显存和推理速度？
8. 一个微调项目写进简历时，哪些内容最有说服力？

## 8. 常见误区

1. 误区：微调可以把所有新知识都塞进模型。  
   解释：微调更擅长学习风格、格式、任务习惯和稳定行为。大量动态知识更适合 RAG。

2. 误区：模型越大，项目越高级。  
   解释：初学项目更看重闭环能力。能用小模型把数据、训练、评估、部署讲清楚，比只说训练大模型更可靠。

3. 误区：loss 下降就代表模型变好。  
   解释：loss 只是训练集上的拟合信号，模型可能背训练数据，却在真实问题上变差。

4. 误区：先学完所有原理再动手。  
   解释：微调是工程技能，很多概念需要边跑边理解。

## 9. 本节总结

微调学习要按完整流程推进：选型、数据、训练、日志、评估、部署、项目表达。初学者不要追求一开始就训练大模型，而要先完成一个小而闭环的项目。7 天计划适合入门，14 天计划适合系统学习，30 天计划适合做成作品和简历项目。
