# 04 微调常见方法详解

## 1. 这一节要解决什么问题

这一节帮你建立主流微调方法地图，知道 Full Fine-tuning、SFT、LoRA、QLoRA、DPO、Adapter、PEFT 分别是什么、适合什么场景。

## 2. 基础概念解释

### Full Fine-tuning 全量微调

通俗解释：全量微调像把整本教材都重新批注一遍，改动范围很大。

技术解释：Full Fine-tuning 会更新模型的大部分或全部参数，训练成本和显存需求较高。

例子：对 7B 模型做全量微调，通常需要更强 GPU 和更细致的训练配置。

### PEFT 参数高效微调

通俗解释：PEFT 像不给整栋楼重新装修，而是在关键房间加装设备，省钱省时间。

技术解释：PEFT 是 Parameter-Efficient Fine-tuning，只训练少量新增参数或部分参数，降低显存和存储成本。

例子：LoRA、Adapter 都属于常见 PEFT 方法。

### Adapter

通俗解释：Adapter 像在老设备上插一个转接头，让它适配新任务。

技术解释：Adapter 是在模型层中插入小型可训练模块，冻结原模型，只训练这些模块。

例子：为同一个基础模型训练多个 Adapter，可以分别适配客服、摘要、分类任务。

### RLHF

通俗解释：RLHF 像让评委给多个答案打分，再让模型学会更讨人喜欢的回答。

技术解释：RLHF 是 Reinforcement Learning from Human Feedback，通常先训练奖励模型，再用强化学习优化语言模型。

例子：人类更喜欢“准确、礼貌、简洁”的答案，RLHF 会推动模型往这种偏好靠近。

### DPO

通俗解释：DPO 像直接告诉模型“A 答案比 B 答案好”，不单独训练一个评委。

技术解释：DPO 是 Direct Preference Optimization，用 chosen/rejected 偏好对直接优化模型，使其更偏向被选中的回答。

例子：同一个问题下，chosen 是清楚回答，rejected 是啰嗦或错误回答。

## 3. 为什么要学这个

不同微调方法的成本、数据格式和目标都不同。初学者如果不先理解方法地图，很容易把 SFT、LoRA、QLoRA、DPO 混在一起。正确理解它们，才能在项目中说清楚“为什么选 LoRA，而不是全量微调或 DPO”。

## 4. 关键知识点

### 4.1 方法总览

解释：微调方法可以按“训练目标”和“训练多少参数”两个角度理解。

例子：

| 方法 | 核心目标 | 训练范围 | 数据类型 | 初学推荐 |
| --- | --- | --- | --- | --- |
| Full Fine-tuning | 全模型适配 | 大量参数 | 指令或任务数据 | 不推荐首选 |
| SFT | 学标准答案 | 可全量也可 LoRA | 输入输出样例 | 推荐 |
| LoRA | 低成本适配 | 少量新增参数 | 指令或任务数据 | 强烈推荐 |
| QLoRA | 更省显存 LoRA | 量化模型 + LoRA | 指令或任务数据 | 推荐但环境更挑 |
| Adapter | 插入小模块 | 小模块参数 | 任务数据 | 了解即可 |
| DPO | 学人类偏好 | 可全量也可 LoRA | chosen/rejected | 进阶 |
| RLHF | 偏好和奖励优化 | 复杂流程 | 人类反馈 | 理论了解 |

注意事项：SFT 是训练目标，LoRA 是训练方式。你可以“用 LoRA 做 SFT”，这两个不是互斥关系。

### 4.2 Full Fine-tuning

解释：全量微调改动大，潜力强，但成本高，也更容易破坏原模型能力。

例子：如果你有大量高质量行业数据、强算力和严格评估，可以考虑全量微调。

注意事项：初学者不要把全量微调作为第一个项目。显存、训练稳定性、灾难性遗忘都会更难处理。

### 4.3 SFT

解释：SFT 是最常见的指令微调方法，核心是让模型模仿标准答案。

例子：

```json
{
  "instruction": "请解释什么是 batch size",
  "input": "",
  "output": "batch size 是一次训练送进模型的样本数量，可以理解为一次批改几道题。"
}
```

注意事项：SFT 数据质量决定上限。错答案、口吻混乱、格式不统一都会被模型学进去。

### 4.4 LoRA

解释：LoRA 冻结原模型，只训练少量低秩矩阵，是初学者最适合上手的微调方式。

例子：你可以为同一个基础模型训练一个“客服 LoRA”和一个“代码解释 LoRA”，需要时加载对应 LoRA。

注意事项：LoRA 不是魔法。数据太少、任务太宽、基础模型太弱，LoRA 也救不了。

### 4.5 QLoRA

解释：QLoRA 在 4bit 量化模型上训练 LoRA，进一步降低显存需求。

例子：同样的 7B 模型，QLoRA 可能比普通 LoRA 更容易在有限显存上跑起来。

注意事项：QLoRA 对环境依赖更敏感，尤其是 `bitsandbytes`、CUDA、GPU 架构。Windows 用户可能更适合 WSL/Linux 或云 GPU。

### 4.6 DPO

解释：DPO 不是让模型模仿唯一标准答案，而是让模型知道哪个答案更好。

例子：

```json
{
  "prompt": "解释 LoRA",
  "chosen": "LoRA 是一种参数高效微调方法，只训练少量新增参数。",
  "rejected": "LoRA 就是随便调一下模型。"
}
```

注意事项：DPO 通常建立在已有 SFT 模型之上。初学者先学 SFT 和 LoRA，再学 DPO 会更顺。

### 4.7 Adapter

解释：Adapter 也是参数高效微调方法，会在模型层之间插入小模块。

例子：一个基础模型配多个 Adapter，就像一个主机配多个可插拔模块。

注意事项：当前很多开源教程更偏 LoRA，初学项目优先 LoRA，Adapter 了解概念即可。

## 6. 实战任务

为下面三个任务选择微调方法：

1. 低显存环境下训练一个领域问答助手。
2. 有大量标注问答，希望模型按标准答案回答。
3. 已有两个答案的优劣偏好数据，希望模型更符合人工偏好。

要求：每个任务写出“选择的方法、需要的数据、为什么不选其他方法”。

## 8. 常见误区

1. 误区：LoRA 就是 SFT。  
   解释：LoRA 是参数高效训练方式，SFT 是监督微调目标，可以用 LoRA 做 SFT。

2. 误区：QLoRA 一定比 LoRA 效果好。  
   解释：QLoRA 主要优势是省显存，不是天然更强。

3. 误区：DPO 可以替代所有 SFT。  
   解释：DPO 更适合偏好优化，通常需要模型已有基本指令能力。

4. 误区：全量微调最专业，所以项目一定要用它。  
   解释：真实工程看成本和收益，LoRA 往往更适合中小项目。

## 9. 本节总结

微调方法要分清训练目标和训练方式。SFT 负责模仿标准答案，DPO 负责学习偏好，LoRA/QLoRA/Adapter 负责降低训练成本。初学者最推荐从“LoRA + SFT”开始，先完成一个小而完整的项目。
