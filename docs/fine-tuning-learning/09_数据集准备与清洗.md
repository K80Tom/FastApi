# 09 数据集准备与清洗

## 1. 这一节要解决什么问题

这一节教你把原始资料变成可训练数据，理解数据来源、格式转换、清洗规则、质量检查和训练集划分。

## 2. 基础概念解释

### Dataset 数据集

通俗解释：数据集是模型的练习册。练习册质量越好，学生越容易学对。

技术解释：Dataset 是训练、验证、测试使用的样本集合，可以是 JSONL、CSV、Parquet 或 HuggingFace Dataset。

例子：一个领域问答数据集包含 1000 条“问题和答案”。

### 数据清洗

通俗解释：数据清洗像改练习册，把错题、重复题、印刷乱码和不适合的题删掉或改好。

技术解释：数据清洗是对原始数据进行去重、过滤、格式校验、敏感信息处理、质量评分和字段标准化。

例子：删除答案为空、问题太短、含乱码、重复的训练样例。

### Train/Validation/Test

通俗解释：训练集像平时练习，验证集像阶段测验，测试集像期末考试。

技术解释：Train 用于更新模型，Validation 用于训练中观察效果，Test 用于最终评估泛化能力。

例子：1000 条数据可以划分为 800 条训练、100 条验证、100 条测试。

## 3. 为什么要学这个

微调项目的上限常常由数据决定。很多训练失败不是代码问题，而是数据问题：答案错误、格式混乱、重复太多、覆盖不足、训练集和测试集泄漏。掌握数据准备，你才真正能做微调项目。

## 4. 关键知识点

### 4.1 数据来源

解释：初学者项目可以从公开数据、业务文档、人工构造和模型辅助生成开始。

例子：

| 来源 | 优点 | 风险 | 建议 |
| --- | --- | --- | --- |
| 公开数据集 | 容易获取 | 可能不贴合项目 | 用于练手 |
| 业务文档 | 真实 | 可能涉及隐私 | 脱敏后使用 |
| 人工编写 | 质量可控 | 数量少 | 适合小项目 |
| 模型生成 | 快速扩充 | 可能有错 | 必须人工抽查 |

注意事项：不要把敏感数据、个人隐私或公司内部机密直接放进训练集。

### 4.2 Alpaca 数据格式

解释：适合单轮指令任务。

例子：

```jsonl
{"instruction":"解释什么是 LoRA","input":"","output":"LoRA 是一种参数高效微调方法，只训练少量新增参数。"}
{"instruction":"判断是否适合微调","input":"公司制度每周更新，需要引用原文。","output":"不优先微调，更适合 RAG，因为知识更新频繁且需要引用来源。"}
```

注意事项：`output` 不要为空。`instruction` 不要过于模糊。

### 4.3 ShareGPT 数据格式

解释：适合多轮聊天助手。

例子：

```jsonl
{"conversations":[{"from":"human","value":"我该先学 LoRA 还是 DPO？"},{"from":"gpt","value":"建议先学 LoRA。LoRA 是低成本训练方式，DPO 是偏好优化，通常放在 SFT 之后。"}]}
```

注意事项：多轮数据要保留角色顺序。不要把 human 和 gpt 写反。

### 4.4 数据清洗流程

解释：清洗要先做格式检查，再做内容质量检查。

例子：

```text
原始资料
-> 抽取问答或构造指令
-> 统一字段
-> 去重
-> 删除空答案和乱码
-> 过滤过长或过短样例
-> 检查事实正确性
-> 脱敏
-> 划分 train/validation/test
-> 保存 JSONL
```

注意事项：每一步都要记录规则，否则以后无法复现。

### 4.5 最小数据检查脚本

解释：下面脚本用于检查 JSONL 是否能逐行解析，并统计关键字段。

例子：

```python
import json
from pathlib import Path

path = Path("data/train.jsonl")
bad_lines = []
empty_outputs = 0

with path.open("r", encoding="utf-8") as f:
    for line_no, line in enumerate(f, start=1):
        try:
            row = json.loads(line)
        except json.JSONDecodeError:
            bad_lines.append(line_no)
            continue

        output = row.get("output", "")
        if not str(output).strip():
            empty_outputs += 1

print("bad json lines:", bad_lines)
print("empty outputs:", empty_outputs)
```

注意事项：这个脚本适合 Alpaca 格式。ShareGPT 格式要检查 `conversations` 数组。

### 4.6 数据划分

解释：不要把同一类重复样例同时放到训练集和测试集，否则评估会虚高。

例子：如果 10 条问题只是把“什么是 LoRA”换了不同说法，不要 9 条放训练、1 条放测试。

注意事项：测试集要尽量模拟真实用户问题，而不是训练集的轻微改写。

### 4.7 数据版本管理

解释：数据也要像代码一样管理版本。

例子：

```text
data/
├── raw/
├── processed/
├── train.jsonl
├── valid.jsonl
└── test.jsonl
```

注意事项：保留清洗脚本和数据说明，简历项目里这会显得很专业。

前面 SFT、DPO 都依赖数据格式。本节讲如何准备数据。后面的训练参数、日志和评估，都要基于稳定的数据集才能有意义。

## 6. 实战任务

完成一个 20 条小数据集：

1. 选择主题：“Fine-tuning 学习助手”或你自己的领域。
2. 写 20 条 Alpaca JSONL。
3. 检查每条是否有 `instruction` 和 `output`。
4. 删除重复或太模糊的问题。
5. 划分 16 条训练、2 条验证、2 条测试。

## 8. 常见误区

1. 误区：数据越多一定越好。  
   解释：错误数据越多，模型学错越稳定。

2. 误区：测试集可以从训练集复制几条。  
   解释：这会导致评估虚高，不能代表真实泛化。

3. 误区：清洗只需要去重。  
   解释：还要检查格式、事实、长度、隐私、覆盖面。

4. 误区：让大模型生成数据就不用人工检查。  
   解释：大模型也会编造和犯错，训练数据必须抽查。

## 9. 本节总结

数据准备是微调项目最重要的环节之一。你需要把原始资料变成清晰、正确、统一的 Alpaca 或 ShareGPT 样例，并做好清洗、脱敏、划分和版本管理。高质量小数据集往往比大量脏数据更有价值。
