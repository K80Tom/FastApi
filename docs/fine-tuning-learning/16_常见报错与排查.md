# 16 常见报错与排查

## 1. 这一节要解决什么问题

这一节提供初学者微调最常见问题的排查表，帮助你遇到显存、环境、数据、训练、推理错误时知道先查哪里。

## 2. 基础概念解释

### OOM

通俗解释：OOM 像桌子太小，模型、数据和中间结果摆不下。

技术解释：OOM 是 Out Of Memory，通常指 GPU 显存或系统内存不足。

例子：训练时报 `CUDA out of memory`。

### CUDA

通俗解释：CUDA 像 NVIDIA GPU 的高速公路，深度学习框架通过它调用 GPU。

技术解释：CUDA 是 NVIDIA 的并行计算平台，PyTorch、bitsandbytes 等库需要与 CUDA 版本匹配。

例子：torch 安装的 CUDA 版本和系统驱动不兼容，会导致 GPU 不可用。

### 依赖冲突

通俗解释：依赖冲突像几个人同时要求你用不同版本的同一本教材。

技术解释：依赖冲突是 Python 包版本之间不兼容，导致导入、训练或运行时报错。

例子：`trl` 版本更新后，`SFTTrainer` 参数名变化。

## 3. 为什么要学这个

微调新手大量时间会花在报错上。会排查报错不是低级技能，而是工程能力。你要学会从错误关键词判断问题类型，而不是看到红字就重装环境。

## 4. 关键知识点

### 4.1 排查总流程

解释：先定位错误类型，再小步验证。

例子：

```text
1. 复制完整报错。
2. 找最后一个关键错误行。
3. 判断是环境、显存、数据、参数、模型加载还是推理问题。
4. 用最小样例复现。
5. 每次只改一个地方。
6. 记录解决方法。
```

注意事项：不要边报错边大改代码。改太多会不知道哪个改动有效。

### 4.2 初学者常见问题排查表

解释：下面是常见问题和优先处理方向。

例子：

| 问题 | 典型报错或现象 | 可能原因 | 优先处理 |
| --- | --- | --- | --- |
| 显存不足 | CUDA out of memory | batch、seq_len、模型太大 | batch=1，降 seq_len，用 QLoRA |
| GPU 不可用 | torch.cuda.is_available 为 False | 驱动或 torch CUDA 版本不匹配 | 检查驱动、torch 安装 |
| bitsandbytes 报错 | cannot load library | 环境不兼容 | 用 Linux/WSL 或换版本 |
| target module 不存在 | target_modules not found | 模型层名不同 | 打印模型结构 |
| 数据字段错误 | column not found | JSONL 字段名不匹配 | 检查 dataset_text_field |
| JSON 解析失败 | JSONDecodeError | JSONL 某行不合法 | 定位行号修复 |
| loss 为 nan | loss nan | 学习率高、精度不稳 | 降 lr，检查 fp16/bf16 |
| loss 不下降 | loss 平 | 数据模板错或 lr 太低 | 检查样例和 prompt |
| 输出乱码 | 乱码或重复 | Tokenizer 不匹配 | 使用同一模型 Tokenizer |
| LoRA 加载失败 | adapter config missing | 路径不对或保存不完整 | 检查 adapter_config.json |
| 推理很慢 | 每次很久 | CPU 推理或模型太大 | 用 GPU、小模型、量化 |
| 答案太长 | 啰嗦停不下 | max_new_tokens 高或数据风格长 | 限制长度，补简洁样例 |

注意事项：排查时先从最常见的 batch、数据字段、路径、版本查起。

### 4.3 显存不足处理

解释：显存不足最常见，先用保守策略。

例子：

```text
1. per_device_train_batch_size = 1
2. max_seq_length = 512
3. gradient_accumulation_steps = 4 或 8
4. LoRA r 从 16 降到 8 或 4
5. 使用 QLoRA 4bit
6. 换更小模型
```

注意事项：不要直接把所有参数都降到最低，否则训练可能很慢或效果差。一步一步来。

### 4.4 数据格式错误

解释：很多训练代码报错是字段名不匹配。

例子：代码写 `dataset_text_field="text"`，但 JSONL 是：

```json
{"instruction":"解释 LoRA","output":"..."}
```

这时没有 `text` 字段，需要转换格式或修改训练代码。

注意事项：训练前先打印第一条数据：

```python
print(dataset[0])
```

### 4.5 target_modules 错误

解释：不同模型层名不同，LoRA 不知道要插在哪里。

例子：有的模型用 `q_proj`、`v_proj`，有的可能用其他命名。

注意事项：可以先打印模型结构，搜索线性层名称，再设置 `target_modules`。

### 4.6 训练效果不好

解释：效果不好不一定是参数问题，可能是数据目标不清。

例子：

```text
表现：回答仍然抽象。
可能原因：训练数据本身没有通俗解释。
处理：补充“通俗解释 + 技术解释 + 例子”的高质量样例。
```

注意事项：先看模型输出失败案例，再决定补数据还是调参数。

### 4.7 推理加载问题

解释：LoRA 推理必须基础模型和 adapter 匹配。

例子：用 A 模型训练的 LoRA adapter，不能随便加载到 B 模型上。

注意事项：README 中记录基础模型名称、版本、adapter 路径。

## 8. 常见误区

1. 误区：报错就重装所有环境。  
   解释：重装可能引入更多变量，应先定位错误类型。

2. 误区：显存不足只能换显卡。  
   解释：可以先从 batch、seq_len、QLoRA 和小模型入手。

3. 误区：loss 不降一定是模型太弱。  
   解释：数据模板、学习率、字段映射都可能导致不学习。

4. 误区：网上复制的参数适合所有模型。  
   解释：不同模型、数据、显卡和库版本都可能需要调整。

## 9. 本节总结

报错排查要按类型定位：环境、显存、数据、参数、模型加载、推理。初学者最常见的是 OOM、字段名错误、依赖版本和 LoRA 加载问题。每次排查都要记录过程，这会成为项目复盘和面试中的加分内容。
