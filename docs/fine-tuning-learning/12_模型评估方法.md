# 12 模型评估方法

## 1. 这一节要解决什么问题

这一节教你评估微调后的模型是否真的变好，包括自动指标、人工评分、A/B 对比、失败案例分析和测试集设计。

## 2. 基础概念解释

### Evaluation 评估

通俗解释：评估像期末考试，不能只看平时练习扣分，还要看新题做得怎么样。

技术解释：Evaluation 是用验证集、测试集、人工标准或自动指标衡量模型在目标任务上的表现。

例子：微调前后各回答 50 个问题，比较准确性、格式稳定性和可读性。

### Baseline 基线

通俗解释：baseline 像跑步前的原始成绩。没有原始成绩，就不知道训练后进步了多少。

技术解释：Baseline 是未微调模型、Prompt 方案或 RAG 方案的参考效果。

例子：先记录基础模型在测试集上的得分，再和 LoRA 模型比较。

### 自动指标

通俗解释：自动指标像机器批卷，速度快但不一定完全懂答案质量。

技术解释：自动指标是用程序计算的分数，例如准确率、格式合法率、BLEU、ROUGE、困惑度等。

例子：JSON 输出任务可以统计合法 JSON 比例和字段准确率。

### 人工评分

通俗解释：人工评分像老师批开放题，更能看懂答案是否真的有用。

技术解释：人工评分是按评分标准对模型回答进行人工打分，常用于开放问答和助手类任务。

例子：从准确性、完整性、清晰度、安全性四个维度每项 1 到 5 分。

## 3. 为什么要学这个

训练完成不等于项目成功。微调可能让模型在某些方面变好，同时在其他方面变差。评估能帮你证明项目效果，也能告诉你下一轮数据和参数该怎么改。

## 4. 关键知识点

### 4.1 评估先看目标

解释：不同项目评估方式不同，不能所有任务都只看 loss。

例子：

| 项目目标 | 评估指标 |
| --- | --- |
| JSON 抽取 | JSON 合法率、字段准确率 |
| 客服问答 | 准确性、礼貌性、解决率 |
| 学习助手 | 通俗度、正确性、结构化程度 |
| 分类任务 | accuracy、precision、recall |
| 摘要任务 | 人工评分、覆盖度、事实一致性 |

注意事项：先定义“好”的标准，再训练。

### 4.2 测试集设计

解释：测试集要覆盖真实使用场景和边界情况。

例子：

```text
简单问题：什么是 LoRA？
对比问题：LoRA 和 QLoRA 区别是什么？
场景判断：公司制度每周更新，是否适合微调？
边界问题：没有 GPU 怎么学习 QLoRA？
无关问题：帮我写一首无关诗歌。
```

注意事项：测试集不要从训练集复制，也不要只放最简单问题。

### 4.3 训练前后对比

解释：同一批问题分别问基础模型和微调模型，比较结果。

例子：

| 问题 | 基础模型 | 微调模型 | 谁更好 | 原因 |
| --- | --- | --- | --- | --- |
| 解释 LoRA | 抽象 | 有类比和例子 | 微调模型 | 更适合初学者 |

注意事项：对比时使用相同 prompt、相同生成参数，保证公平。

### 4.4 人工评分表

解释：开放问答很难完全自动评分，人工评分更实用。

例子：

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 正确性 | 明显错误 | 大体正确有小问题 | 准确 |
| 清晰度 | 看不懂 | 能看懂但不顺 | 清楚易懂 |
| 结构 | 混乱 | 有基本结构 | 层次清晰 |
| 任务贴合 | 偏题 | 基本回答 | 完全贴合 |

注意事项：评分标准要提前定，不要看完结果再改标准。

### 4.5 自动评估脚本思路

解释：结构化任务可以写脚本自动检查。

例子：

```python
import json

def is_valid_json(text: str) -> bool:
    try:
        json.loads(text)
        return True
    except json.JSONDecodeError:
        return False

outputs = ['{"intent":"refund"}', "intent: refund"]
score = sum(is_valid_json(x) for x in outputs) / len(outputs)
print("json_valid_rate:", score)
```

注意事项：自动指标只能覆盖一部分质量，开放问答仍需人工抽查。

### 4.6 失败案例分析

解释：失败案例比平均分更能指导下一步。

例子：

```text
失败类型：
1. 概念说错：补充正确概念数据。
2. 回答太长：加入简洁回答样例。
3. 格式不稳定：增加格式化训练样例。
4. 遇到边界问题胡说：加入拒答或澄清样例。
```

注意事项：不要只挑成功案例展示。项目复盘要能说出失败和改进。

## 5. 和前后知识的关系

前面你学习了训练和日志，本节判断训练结果是否有用。下一节部署会把评估通过的模型提供给用户或应用调用。

## 6. 实战任务

为“基于 LoRA 的领域问答助手”设计一个 20 题测试集：

1. 10 个常见问题。
2. 5 个对比或解释问题。
3. 3 个边界问题。
4. 2 个无关或拒答问题。

然后设计 4 个评分维度，每个维度 1 到 5 分。

## 7. 检查自己是否学会

1. baseline 为什么重要？
2. 为什么不能只看训练 loss？
3. 测试集应该覆盖哪些问题？
4. 自动指标适合什么任务？
5. 人工评分适合什么任务？
6. 训练前后对比要控制哪些变量？
7. 失败案例分析有什么价值？
8. 微调后模型变得更啰嗦，该怎么改？

## 8. 常见误区

1. 误区：训练能跑完就说明效果好。  
   解释：训练只是过程，评估才说明结果。

2. 误区：只展示成功案例。  
   解释：真实项目需要分析失败场景，否则无法迭代。

3. 误区：开放问答可以完全靠自动指标。  
   解释：自动指标难以判断通俗度、事实一致性和帮助性。

4. 误区：测试集可以随便写。  
   解释：测试集决定你评估的可信度，必须贴近真实问题。

## 9. 本节总结

评估是微调闭环的关键。你需要先建立 baseline，再设计测试集，通过自动指标和人工评分比较微调前后效果。失败案例分析能指导下一轮数据清洗和训练参数调整。
