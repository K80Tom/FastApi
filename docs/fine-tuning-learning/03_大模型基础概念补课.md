# 03 大模型基础概念补课

## 1. 这一节要解决什么问题

这一节用零基础能理解的方式补齐 Tokenizer、Transformer、Dataset、JSONL、显存、推理等基础概念，让你后面能看懂微调代码和训练参数。

## 2. 基础概念解释

### Tokenizer 分词器

通俗解释：Tokenizer 像把一句话切成模型能吃的小块。人看的是汉字和单词，模型看的是编号。

技术解释：Tokenizer 把文本转换成 token id，也就是一串整数；模型训练和推理时处理的是这些整数。

例子：`我喜欢AI` 可能被切成 `我`、`喜欢`、`AI`，再映射成 `[123, 4567, 89]`。

### Transformer

通俗解释：Transformer 像一群读文章的助教，会同时看句子里每个词和其他词的关系，判断哪个词更重要。

技术解释：Transformer 是现代大模型的核心网络结构，依靠 attention 机制处理上下文关系。

例子：句子“苹果发布了新手机，它很贵”中，“它”指代新手机，Transformer 会通过上下文关系理解指代。

### Dataset 数据集

通俗解释：Dataset 像练习册，里面有很多题和参考答案。

技术解释：Dataset 是训练、验证或测试时使用的数据集合，通常包含输入、输出、标签、对话等字段。

例子：一条 SFT 数据可以是“instruction=解释 LoRA，output=LoRA 是……”。

### JSONL

通俗解释：JSONL 像一行一张小卡片，每行都是一条完整样例。

技术解释：JSONL 是 JSON Lines 格式，每一行都是合法 JSON 对象，适合大规模逐行读取训练数据。

例子：

```jsonl
{"instruction":"解释 LoRA","input":"","output":"LoRA 是一种参数高效微调方法。"}
{"instruction":"解释 SFT","input":"","output":"SFT 是监督微调。"}
```

### Inference 推理

通俗解释：推理就是训练好的模型开始答题。

技术解释：Inference 是模型参数固定后，根据用户输入生成输出的过程。

例子：微调后你输入“请解释 batch size”，模型生成解释，这就是推理。

## 3. 为什么要学这个

微调代码里的很多错误都来自基础概念没理解。例如数据格式错，是因为不懂 Dataset；显存爆了，是因为不懂 batch size 和模型参数；输出乱码，可能是 Tokenizer 用错。补基础能让你少走很多弯路。

## 4. 关键知识点

### 4.1 文本如何进入模型

解释：模型不能直接读文字，文字要先经过 Tokenizer 变成数字。

例子：

```text
原始文本 -> Tokenizer -> token ids -> 模型 -> 输出 token ids -> 解码成文本
```

注意事项：训练和推理最好使用同一个模型配套的 Tokenizer。Tokenizer 不匹配可能导致输出异常或效果变差。

### 4.2 模型参数和模型大小

解释：模型参数越多，通常容量越大，但训练和推理成本也更高。

例子：7B 模型大约有 70 亿参数，14B 模型大约有 140 亿参数。参数像脑内经验，越多可能越强，但也更占显存。

注意事项：初学者优先选择 0.5B、1.5B、3B 或 7B 的小模型做实验，不要一开始挑战大模型。

### 4.3 显存是什么

解释：显存是 GPU 上的高速内存，训练时要放模型参数、梯度、优化器状态、中间激活值和 batch 数据。

例子：做饭时桌面太小，锅、菜、调料都摆不下，就没法顺利做菜。显存不足也是类似，训练会报 out of memory。

注意事项：降低 batch size、使用 gradient accumulation、开启 QLoRA、缩短 sequence length，都能减轻显存压力。

### 4.4 Quantization 量化

解释：量化像把高清图片压缩成更小文件，牺牲一点精度换取更低内存占用。

技术解释：量化把模型权重从 float16、float32 等高精度格式转换成 int8、int4 等低精度格式，减少显存和存储。

例子：QLoRA 常用 4bit 量化加载基础模型，再训练 LoRA 参数。

注意事项：量化可能带来精度损失。推理量化和训练量化不是一回事，要看具体库支持。

### 4.5 Checkpoint 检查点

解释：checkpoint 像游戏存档，训练到某一步保存一次，后面可以继续训练或拿来推理。

例子：训练目录里可能有 `checkpoint-500`、`checkpoint-1000`，表示第 500 或 1000 step 保存的模型状态。

注意事项：不要只保留最后一个 checkpoint。中间 checkpoint 有时效果更好，尤其是后期过拟合时。

### 4.6 Overfitting 过拟合

解释：过拟合像学生把练习册答案背熟了，但换一套题就不会做。

技术解释：模型在训练集上表现很好，但在验证集或真实问题上表现变差。

例子：训练数据里每条答案都很长，模型学会无论什么问题都输出很长答案，真实体验反而不好。

注意事项：要划分验证集和测试集，观察训练 loss 和验证 loss 的差异。

## 5. 和前后知识的关系

## 8. 常见误区

1. 误区：模型直接理解中文字符。  
   解释：模型处理的是 token id，文字必须先编码。

2. 误区：显存只和模型大小有关。  
   解释：batch size、序列长度、优化器、梯度都会占显存。

3. 误区：checkpoint 越靠后越好。  
   解释：后期可能过拟合，要用验证集和测试集判断。

4. 误区：量化一定不影响效果。  
   解释：量化会降低精度，只是很多场景损失可接受。

## 9. 本节总结

大模型训练的输入不是文字，而是 Tokenizer 生成的 token id。Dataset 和 JSONL 决定模型练什么题，显存决定你能不能跑得动，loss 和 checkpoint 帮你观察训练过程。理解这些基础，后面看 LoRA、QLoRA 和训练日志会轻松很多。
