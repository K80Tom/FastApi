# 附录E 显存估算速查 + 开源微调框架对比

## 1. 这一节要解决什么问题

让你在动手前能大致估出“这个模型用这种方法，我的显卡够不够”，不再盲目开跑撞 OOM；同时认识主流开源微调框架，看 GitHub 项目时知道它们是干什么的、该选哪个。

## 2. 基础概念解释

### 显存占用的来源

通俗解释：训练时显存像一张桌子，要同时摆四样东西——模型本身、它的“梯度”、优化器的“小账本”、还有算到一半的中间结果。桌子摆不下就 OOM。

技术解释：训练显存 ≈ 模型权重 + 梯度 + 优化器状态 + 激活值。全量微调时后三者是大头，LoRA/QLoRA 通过冻结主体大幅削减梯度和优化器开销，量化再压缩权重本身。

例子：同样 7B 模型，全量微调要几十 GB，QLoRA 可能十几 GB 就够。

### 微调框架

通俗解释：框架像“装修队”，底层工具(transformers/peft/trl)是“水泥钢筋”，框架把它们打包成开箱即用的流程，你填配置就能开工。

技术解释：微调框架在 transformers/peft/trl 之上封装了数据处理、训练循环、配置管理、多卡支持，降低上手成本。

例子：用 LLaMA-Factory，你改一个 yaml 配置就能跑 LoRA，不用自己写训练脚本。

## 3. 为什么要学这个

显存估算让你提前选对模型和方法，省下大量试错时间；框架认知让你看懂 GitHub 上的真实项目(它们极少用裸 transformers 手写)，也让你做项目时不必从零造轮子。这是从“跑通玩具 Demo”走向“看懂/复用真实项目”的关键一步。

## 4. 关键知识点

### 4.1 显存粗估口诀

解释：记几个经验数，按方法乘系数。下面是推理/训练的**粗略**经验值，实际受序列长度、batch、框架影响。

例子：

**推理(只加载模型跑)，按精度估算每 1B 参数大约占用：**

| 精度 | 每 1B 参数约占 | 7B 模型推理约需 |
| --- | --- | --- |
| fp16 / bf16 (16bit) | 2 GB | ~14 GB |
| int8 (8bit) | 1 GB | ~7 GB |
| int4 (4bit) | 0.5 GB | ~4 GB |

**训练，按方法估算 7B 模型大约需要：**

| 方法 | 7B 大约需要 | 说明 |
| --- | --- | --- |
| 全量微调(fp16+Adam) | 60-80 GB | 权重+梯度+优化器，最吃显存 |
| LoRA(fp16 加载) | 16-20 GB | 主体冻结，只训小矩阵 |
| QLoRA(4bit 加载) | 8-12 GB | 量化省权重，最省 |

注意事项：这些是**量级参考**，不是精确值。序列长度(max_seq_length)和 batch size 越大，激活值越多，显存越高。估出来后留 20% 余量更稳。

### 4.2 按显卡选方案

解释：反过来用——先看你有多大显存，再决定能玩多大模型。

例子：

| 你的显存 | 推荐做法 |
| --- | --- |
| 6-8 GB | 0.5B/1.5B 模型 LoRA/QLoRA，或 3B QLoRA 短序列 |
| 12 GB | 7B QLoRA(短序列)、3B LoRA |
| 16-24 GB | 7B QLoRA 舒适、7B LoRA、14B QLoRA 紧凑 |
| 40 GB+ | 7B 全量、更大模型 QLoRA |

注意事项：显存不够时的标准三连：① batch size 降到 1 + 加大梯度累积；② 缩短 max_seq_length；③ 换 QLoRA(4bit)。还不行就换更小模型或租更大显卡。

### 4.3 主流开源微调框架对比

解释：这四个是 GitHub 上最常见的，各有定位。

例子：

| 框架 | 一句话定位 | 上手难度 | 适合谁 |
| --- | --- | --- | --- |
| **LLaMA-Factory** | 配置化全能框架，改 yaml/网页点选就能跑，支持几乎所有方法和主流模型 | 低 | 初学者首选、快速出活 |
| **Unsloth** | 主打“快和省显存”，对单卡 LoRA/QLoRA 做了深度优化，有现成 Colab notebook | 低 | 单卡、显存紧张、想跑快 |
| **Axolotl** | 配置化，社区活跃，灵活度高，偏工程化 | 中 | 有一定经验、要定制 |
| **trl + peft(裸写)** | 自己写训练脚本，最灵活也最需要懂原理 | 高 | 学原理、深度定制(本资料 05/06/附录C 走的就是这条) |

注意事项：**学习阶段建议先用裸 trl+peft 跑一遍(理解每步在干嘛)，再用 LLaMA-Factory 或 Unsloth 提效**。直接上框架容易“跑通了但不知道为什么”。

### 4.4 框架怎么快速上手

解释：以 LLaMA-Factory 为例的看项目套路。

例子：

```text
1. 看 README：支持哪些模型、哪些方法、怎么装
2. 找 examples/ 里的示例 yaml：照着改 model_name、dataset、output_dir
3. 看 data/ 的数据格式约定：把你的数据转成它要的格式(用附录B 脚本)
4. 跑训练命令：llamafactory-cli train your_config.yaml
5. 看输出目录的 adapter，再 merge、推理(同附录C 思路)
```

注意事项：框架封装得越好，越要警惕“黑盒感”。遇到效果不好，回到本资料 10(参数)、11(日志)、12(评估)排查，原理是相通的。

1. 用 4.1 口诀估算：你想微调的模型 + 方法，大概需要多少显存？写下计算过程。
2. 对照 4.2 表，判断你的环境(本地或云)够不够，不够的话写出你的三连降显存方案。

## 7. 检查自己是否学会

1. 训练显存由哪四部分组成？哪部分在全量微调时最大？
2. fp16 下 7B 模型推理大约要多少显存？4bit 呢？
3. 为什么 QLoRA 比 LoRA 还省显存？
4. 显存不够的标准三连是什么？
5. LLaMA-Factory 和 Unsloth 各自的主打卖点是什么？
6. 为什么建议先裸写 trl 再用框架？
7. 序列长度和 batch size 怎么影响显存？
8. 拿到一个陌生微调框架，你按什么顺序看它？

## 8. 常见误区

1. 误区：显存只要够装下模型就能训练。  
   解释：训练还要放梯度、优化器、激活值，比推理多得多。

2. 误区：估算值就是精确值。  
   解释：那是量级参考，实际受序列长度、batch、框架实现影响，要留余量。

3. 误区：框架越高级越该一开始就用。  
   解释：跳过原理直接用框架，遇到问题会无从下手。先懂再提效。

4. 误区：换个框架就能解决效果差的问题。  
   解释：效果差多半是数据或参数问题，换框架不改本质，得回到数据和评估。

## 9. 本节总结

显存粗估记两组数：推理按精度(16bit≈2GB/B、4bit≈0.5GB/B)，训练按方法(全量最贵、LoRA 省、QLoRA 最省)。显存不够就用 batch=1+梯度累积、缩序列、换 QLoRA 三连。框架四选一：初学用 LLaMA-Factory，单卡省显存用 Unsloth，要灵活用 Axolotl，学原理用裸 trl+peft。建议先裸写跑通理解原理，再用框架提效。
