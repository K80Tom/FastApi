# 17 学习复盘与面试题

## 1. 这一节要解决什么问题

这一节帮你复盘整套微调学习内容，提供学习笔记模板、复盘模板、面试题和参考回答，让你能把知识真正讲出来。

## 2. 基础概念解释

### 复盘

通俗解释：复盘像做完一道菜后回头想，哪里切得慢、哪里火太大、下次怎么更好。

技术解释：复盘是对学习或项目过程进行结构化总结，包括目标、行动、结果、问题、原因和下一步。

例子：训练 loss 不降，复盘后发现是数据字段没有被训练器读取。

### 学习笔记

通俗解释：学习笔记不是抄书，而是给未来的自己写说明书。

技术解释：学习笔记应记录概念理解、代码入口、参数含义、实验结果、报错和反思。

例子：记录“LoRA r=8 时训练快，r=16 时显存更高，但小数据效果没有明显提升”。

### 面试题

通俗解释：面试题像别人确认你是不是真的做过、懂不懂。

技术解释：面试题会围绕概念、方案选型、工程细节、评估结果和问题排查展开。

例子：“为什么你的项目用 LoRA，而不是全量微调？”

## 3. 为什么要学这个

学完不等于会讲。真正掌握微调，需要你能解释概念、读懂项目、复现流程、回答追问。复盘能把零散知识变成自己的体系，面试准备能逼你发现理解漏洞。

## 4. 关键知识点

### 4.1 微调学习笔记模板

解释：每学一节都按固定模板记，避免只收藏不理解。

例子：

```markdown
# 微调学习笔记

## 今天学的主题

## 我用一句话解释

## 通俗类比

## 技术解释

## 关键术语
- 术语：
- 我的理解：
- 例子：

## 代码入口
- README：
- train.py：
- config.yaml：
- dataset.jsonl：
- eval.py：

## 关键参数
- batch size：
- learning rate：
- epoch：
- LoRA r：
- max_seq_length：

## 我动手做了什么

## 遇到的问题

## 我怎么解决

## 还没懂的问题

## 下次行动
```

注意事项：笔记一定要写“我的理解”和“例子”，不要只复制定义。

### 4.2 如何看 GitHub 微调项目

解释：按固定顺序看项目，效率最高。

例子：

```text
1. README：项目目标、模型、数据、运行命令。
2. requirements.txt 或 pyproject.toml：依赖版本。
3. configs：训练参数和模型路径。
4. data 示例：字段格式。
5. train.py：模型加载、数据处理、Trainer。
6. eval.py：评估方式。
7. serving 或 app.py：部署方式。
8. issues：常见报错。
```

注意事项：不要一打开就钻进所有源码。先看入口和数据流。

### 4.3 如何看训练代码

解释：训练代码只要先抓住五条线。

例子：

```text
模型线：AutoModel 从哪里加载？
分词线：Tokenizer 是否匹配？
数据线：Dataset 字段如何转成 prompt？
参数线：TrainingArguments 从哪里来？
保存线：checkpoint 和 final model 保存到哪里？
```

注意事项：看不懂函数细节时，先画流程图。

### 4.4 如何看数据集

解释：先看一条样例，再看整体统计。

例子：

```text
字段名：
输入是什么：
输出是什么：
是否多轮：
平均长度：
是否有空答案：
是否有重复：
是否有隐私：
是否和目标一致：
```

注意事项：数据集如果目标混乱，训练代码再好也救不了。

### 4.5 如何看训练日志

解释：日志要结合参数和数据看。

例子：

```text
loss 是否整体下降？
eval loss 是否同步下降？
learning rate 是否正常变化？
是否出现 nan？
每 step 用时是否合理？
checkpoint 是否正常保存？
```

注意事项：不要把单个 loss 点当结论。

### 4.6 如何复盘项目

解释：复盘要回答“我做对了什么，哪里错了，下次怎么改”。

例子：

```markdown
# 项目复盘

## 目标

## 最终结果

## 有效做法

## 失败案例

## 失败原因

## 数据问题

## 参数问题

## 部署问题

## 下一步优化
```

注意事项：复盘里写失败不是扣分，能说出改进方案是加分。

### 4.7 微调面试题和参考回答

解释：以下问题覆盖概念、选型、数据、训练、评估、部署。

例子：

| 面试题 | 参考回答 |
| --- | --- |
| 什么是微调？ | 微调是在已有预训练模型基础上，用特定任务数据继续训练，让模型在目标任务、格式或风格上更稳定。 |
| 微调和 RAG 有什么区别？ | RAG 不改模型参数，主要通过检索外部知识回答；微调会更新参数或 adapter，主要学习行为和输出模式。 |
| 什么情况下不该微调？ | 知识频繁更新、需要引用来源、数据很少、Prompt 能解决、没有评估标准时，不应优先微调。 |
| SFT 是什么？ | SFT 是监督微调，用输入和标准答案训练模型，让模型模仿目标回答。 |
| LoRA 为什么省显存？ | LoRA 冻结基础模型，只训练少量新增低秩矩阵，减少梯度和优化器状态占用。 |
| QLoRA 和 LoRA 区别？ | QLoRA 在量化加载基础模型的情况下训练 LoRA，通常用 4bit 降低显存。 |
| DPO 解决什么问题？ | DPO 用 chosen/rejected 偏好数据，让模型更偏向更好的回答，常用于 SFT 后偏好优化。 |
| Alpaca 和 ShareGPT 格式区别？ | Alpaca 适合单轮 instruction/input/output，ShareGPT 适合多轮 conversations。 |
| learning rate 太大会怎样？ | 可能导致 loss 波动、发散甚至 nan。 |
| 过拟合怎么看？ | train loss 下降但 eval loss 上升，真实测试效果变差。 |
| 显存不够怎么办？ | 降 batch、缩短 seq_len、梯度累积、用 QLoRA、减小 LoRA r、换小模型。 |
| 怎么评估微调模型？ | 建 baseline 和测试集，比较训练前后输出，结合自动指标和人工评分，并分析失败案例。 |
| LoRA 怎么部署？ | 可以基础模型加 adapter 动态加载，也可以 merge 后部署，用 FastAPI、vLLM 或 Ollama 提供调用。 |
| 为什么不用全量微调？ | 全量微调成本高、显存需求大，中小数据和资源有限场景下 LoRA 更合适。 |
| 你的项目最大难点是什么？ | 数据质量和显存限制。通过清洗数据、设计统一输出模板、降低 batch、使用 QLoRA 思路解决。 |

注意事项：参考回答要改成自己的项目，不要背模板。

### 4.8 面试回答结构

解释：回答技术问题要先给结论，再解释原因，再举项目例子。

例子：

```text
问题：为什么选择 LoRA？
回答：
结论：因为项目是中小规模领域问答适配，LoRA 成本更低。
原因：它冻结基础模型，只训练少量 adapter，显存和存储占用小。
例子：我的项目中目标是统一回答结构，不需要全量修改模型能力，所以用 LoRA + SFT。
反思：如果未来有更大规模领域数据和算力，可以比较全量微调或继续预训练。
```

注意事项：面试回答要避免只堆术语。

## 5. 和前后知识的关系

本节是整套学习的收口。前面每章是知识和实践，本节把它们变成自己的笔记、项目复盘和面试表达。学完后你应该能从概念讲到项目细节。

## 6. 实战任务

完成一次总复盘：

1. 用 300 字解释“大模型微调是什么”。
2. 用表格比较 Prompt、RAG、微调、继续预训练。
3. 写一份微调项目 README 简版。
4. 写 10 个你可能被追问的问题。
5. 录音 2 分钟讲你的项目，再听一遍，找出不清楚的地方。

## 7. 检查自己是否学会

1. 你能不用术语解释 LoRA 吗？
2. 你能说清 SFT、DPO、RLHF 的区别吗？
3. 你能解释你的数据格式吗？
4. 你能看懂训练日志里的 loss 和 eval loss 吗？
5. 你能说明显存不够时怎么处理吗？
6. 你能讲出训练前后如何评估吗？
7. 你能把项目用 1 分钟讲清楚吗？
8. 你能回答为什么不用 RAG 或全量微调吗？
9. 你能说出项目下一步优化方向吗？
10. 你能承认一个项目不足并给出改进方案吗？

## 8. 常见误区

1. 误区：面试只要背概念。  
   解释：面试会追问项目细节，必须能讲数据、参数、日志和评估。

2. 误区：复盘只写成功。  
   解释：真实复盘要写失败原因和下一步，这更可信。

3. 误区：笔记越长越好。  
   解释：好笔记要能帮助复现和解释，不是复制资料。

4. 误区：不会回答就硬编。  
   解释：更好的回答是说明自己做过什么、没做什么、下一步如何验证。

## 9. 本节总结

复盘和面试准备是把知识变成能力的最后一步。你需要用自己的话解释概念，用项目细节证明实践，用评估结果说明价值。能讲清楚“为什么这么做、怎么做、效果如何、哪里还能改”，才算真正掌握微调入门。
