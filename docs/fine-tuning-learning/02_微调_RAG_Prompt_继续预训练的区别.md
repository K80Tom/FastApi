# 02 微调 RAG Prompt 继续预训练的区别

## 1. 这一节要解决什么问题

这一节帮你判断一个大模型项目到底该用 Prompt、RAG、微调，还是继续预训练，避免一遇到效果不好就盲目训练。

## 2. 基础概念解释

### Prompt Engineering 提示词工程

通俗解释：Prompt 像给一个聪明同事写清楚任务说明，告诉他角色、要求、格式和注意事项。

技术解释：Prompt Engineering 是通过设计输入文本，引导大模型产生更符合目标的输出，不改变模型参数。

例子：在问题前加“请用三段式回答：概念、例子、注意事项”，模型可能马上输出更规整。

### RAG 检索增强生成

通俗解释：RAG 像开卷考试。模型先查资料，再根据资料回答。

技术解释：RAG 是 Retrieval-Augmented Generation，把用户问题先用于检索外部知识库，再把检索结果和问题一起交给模型生成答案。

例子：公司制度问答系统先从文档库找到“报销标准”段落，再让模型回答。

### Fine-tuning 微调

通俗解释：微调像让同事参加专项培训，让他形成某种稳定回答习惯。

技术解释：微调通过训练数据更新模型参数或新增参数，使模型在某类任务上更符合目标。

例子：训练模型稳定把投诉文本分类成“物流、质量、售后、价格”。

### Continued Pretraining 继续预训练

通俗解释：继续预训练像让一个人继续大量阅读某个行业的书，补行业语言和背景知识。

技术解释：继续预训练是在基础模型上用大量领域无标注文本继续做语言建模训练，目标是增强领域语言分布适应能力。

例子：用大量医学论文继续训练模型，让它更熟悉医学术语，但它不一定会更会聊天或按指令回答。

## 3. 为什么要学这个

企业项目最重要的不是“会不会训练”，而是“会不会选方案”。Prompt 最便宜，RAG 更适合动态知识，微调适合稳定行为，继续预训练适合大量领域语料适配。选错技术会浪费时间、算力和数据。

## 4. 关键知识点

### 4.1 四种方案核心对比

解释：看技术选型时，先比较是否改模型参数、是否依赖外部知识、成本和适用目标。

例子：

| 方案 | 是否改参数 | 主要解决 | 成本 | 适合场景 |
| --- | --- | --- | --- | --- |
| Prompt | 不改 | 指令表达、输出格式 | 低 | 少量规则、快速验证 |
| RAG | 不改 | 引入外部知识 | 中 | 文档问答、知识更新、引用来源 |
| Fine-tuning | 改少量或大量 | 行为、格式、任务习惯 | 中高 | 稳定任务、批量样例 |
| 继续预训练 | 改大量 | 领域语言适配 | 高 | 大量领域语料、基础模型适配 |

注意事项：很多项目会组合使用，例如“RAG + 微调”。RAG 负责查知识，微调负责让回答格式和语气更稳定。

### 4.2 Prompt 适合先试

解释：Prompt 不需要训练，成本最低，是验证需求的第一步。

例子：你想让模型输出 JSON，可以先写：

```text
请只输出 JSON，不要解释。字段包括 intent、entities、confidence。
```

注意事项：如果 Prompt 越写越长、规则越来越多、仍然不稳定，才考虑微调。

### 4.3 RAG 适合知识问答

解释：RAG 的优势是知识可更新、可引用、可追溯。

例子：企业制度文档今天改了报销比例，RAG 只需要更新知识库，模型不需要重新训练。

注意事项：RAG 也可能失败，例如检索不到、检索错、上下文太长、模型没有正确使用资料。不要把 RAG 的检索问题误判成“需要微调”。

### 4.4 微调适合稳定行为

解释：微调的优势是让模型形成稳定模式，特别是风格、格式、分类、抽取和指令跟随。

例子：模型经常把 JSON 多输出解释文字，Prompt 仍不稳定，这时用几百到几千条格式化样例做 SFT 可能有效。

注意事项：微调需要训练集、验证集、测试集。没有评估集就像考试没有试卷，无法判断是否真的提升。

### 4.5 继续预训练适合领域语言适配

解释：继续预训练不一定教模型“怎么答”，更多是让模型熟悉某个领域的文本分布。

例子：法律领域有很多专业表达，例如“诉讼时效”“举证责任倒置”。继续预训练能让模型更熟悉这些语言，但还需要 SFT 才能成为法律问答助手。

注意事项：继续预训练通常成本更高，初学者优先理论理解，不建议作为第一个实战项目。

### 4.6 选型判断流程

解释：按照“能不能用更简单方法解决”的顺序判断。

例子：

```text
1. 只是格式或语气问题？先 Prompt。
2. 需要回答外部资料？先 RAG。
3. 需要稳定输出行为，且有大量样例？考虑微调。
4. 模型完全不熟悉领域语言，且有大量无标注文本？考虑继续预训练。
5. 需要知识和行为都好？RAG + 微调。
```

注意事项：不要因为“微调听起来高级”就选微调。真实项目看收益和维护成本。

## 5. 和前后知识的关系

## 8. 常见误区

1. 误区：RAG 和微调是竞争关系。  
   解释：它们常常是互补关系。RAG 提供知识，微调提供稳定行为。

2. 误区：继续预训练等于 SFT。  
   解释：继续预训练多用无标注文本学习语言分布，SFT 用输入输出样例学习指令行为。

3. 误区：Prompt 效果不好就必须微调。  
   解释：可能是 Prompt 写得不清楚、模型选得不合适、检索质量差，先要定位问题。

4. 误区：微调后就不需要 RAG。  
   解释：模型参数中的知识难更新，企业动态知识仍需要外部知识库。

## 9. 本节总结

Prompt、RAG、微调和继续预训练解决的问题不同。Prompt 成本最低，RAG 适合知识，微调适合稳定行为，继续预训练适合大规模领域语言适配。做项目时先选对方案，再谈训练方法。
