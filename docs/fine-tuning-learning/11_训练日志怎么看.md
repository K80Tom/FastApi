# 11 训练日志怎么看

## 1. 这一节要解决什么问题

这一节教你读懂训练日志中的 loss、learning rate、step、epoch、eval loss、checkpoint，并判断训练是否正常。

## 2. 基础概念解释

### Step

通俗解释：step 像训练中的一次更新脚步。模型走一步，就离目标近一点或远一点。

技术解释：Step 通常表示参数更新次数，不一定等于样本数量，因为可能存在 batch 和梯度累积。

例子：日志显示 `step=100`，表示训练已经进行到第 100 次更新附近。

### Train loss

通俗解释：train loss 像平时练习题扣分。

技术解释：Train loss 是模型在训练数据上的损失，用来观察训练是否在拟合训练集。

例子：从 2.1 降到 1.3，通常说明模型在训练数据上学到了一些模式。

### Eval loss

通俗解释：eval loss 像阶段测验扣分，用来看看练习之外的题会不会。

技术解释：Eval loss 是模型在验证集上的损失，用来观察泛化能力和过拟合风险。

例子：train loss 下降但 eval loss 上升，可能过拟合。

### Checkpoint

通俗解释：checkpoint 是训练存档。

技术解释：Checkpoint 保存某个训练 step 的模型权重、优化器状态或 adapter 权重。

例子：`checkpoint-400` 可能比最后的 `checkpoint-1000` 效果更好。

## 3. 为什么要学这个

不会看日志，就像开车只踩油门不看仪表盘。训练是否发散、是否过拟合、是否太慢、是否显存紧张，都能从日志和保存结果中找到线索。

## 4. 关键知识点

### 4.1 一段典型日志

解释：下面是训练时可能看到的信息。

例子：

```text
{'loss': 1.842, 'learning_rate': 0.00018, 'epoch': 0.2}
{'loss': 1.421, 'learning_rate': 0.00012, 'epoch': 0.8}
{'eval_loss': 1.516, 'epoch': 1.0}
Saving model checkpoint to ./outputs/run1/checkpoint-200
```

注意事项：不要只看单个 loss 点，要看趋势。

### 4.2 正常 loss 趋势

解释：正常情况下，训练初期 loss 会比较明显下降，后期下降变慢。

例子：

```text
2.3 -> 1.8 -> 1.5 -> 1.4 -> 1.35
```

注意事项：loss 有波动很正常，尤其是 batch size 很小时。

### 4.3 异常 loss 趋势

解释：loss 异常通常有几类。

例子：

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| loss 变成 nan | 学习率太大、精度问题 | 降学习率，检查 fp16/bf16 |
| loss 一直不降 | 数据太少、格式错、学习率过低 | 检查数据和模板 |
| train loss 降，eval loss 升 | 过拟合 | 减少 epoch、加数据、加 dropout |
| loss 忽高忽低 | batch 太小或数据差异大 | 增加梯度累积，清洗数据 |

注意事项：出现 nan 要优先处理，继续训练通常没有意义。

### 4.4 看 learning rate

解释：很多训练会使用 warmup 和 decay，学习率不是一直固定。

例子：训练前期从 0 慢慢升到最大值，再逐步下降。

注意事项：如果学习率一直是 0，说明配置可能有问题。若学习率过高且 loss 飙升，需要降低。

### 4.5 看训练速度

解释：日志中 step 用时可以判断训练是否太慢。

例子：小模型一秒几步正常，大模型几十秒一步也可能正常。关键是估算总训练时间。

注意事项：CPU 训练大模型会非常慢。没有 GPU 时可以先用理论阅读或极小模型验证流程。

### 4.6 看 checkpoint

解释：checkpoint 要结合验证集和人工评估选择。

例子：`checkpoint-600` 的 eval loss 最低，最终模型不一定选最后的 `checkpoint-1000`。

注意事项：设置 `save_total_limit` 控制磁盘，不然 checkpoint 会越来越多。

### 4.7 训练记录模板

解释：每次训练都要留下记录，方便复盘。

例子：

```text
实验编号：run_001
模型：
数据版本：
训练方法：LoRA/QLoRA/SFT/DPO
关键参数：lr、batch、epoch、seq_len、r
训练现象：loss 趋势、耗时、显存
最佳 checkpoint：
评估结果：
问题和下一步：
```

注意事项：不要只靠记忆。微调实验很快会混乱。

## 5. 和前后知识的关系

本节接在训练参数之后，用日志来判断参数是否合理。下一节模型评估会进一步说明：日志只能说明训练过程，最终还要看真实任务效果。

## 6. 实战任务

解释下面日志：

```text
step 50 loss 2.10
step 100 loss 1.55
step 150 loss 1.30
eval_loss 1.80
step 200 loss 1.05
eval_loss 2.10
```

回答三个问题：训练集上发生了什么？验证集上发生了什么？你下一步会怎么调？

## 7. 检查自己是否学会

1. step 和 epoch 有什么区别？
2. train loss 下降代表什么？
3. eval loss 上升可能代表什么？
4. 为什么不能只看最后一个 checkpoint？
5. loss 变成 nan 可能是什么原因？
6. batch 很小时 loss 为什么会抖动？
7. 训练记录为什么重要？
8. 什么时候要停止训练？

## 8. 常见误区

1. 误区：loss 每一步都必须下降。  
   解释：小 batch 和随机采样会造成波动，看整体趋势即可。

2. 误区：最后 checkpoint 一定最好。  
   解释：后期可能过拟合，验证集表现可能变差。

3. 误区：train loss 很低就可以上线。  
   解释：还要测试真实任务和安全边界。

4. 误区：日志没报错就代表训练成功。  
   解释：可能数据模板错了，模型学到的是无用格式。

## 9. 本节总结

训练日志是微调过程的仪表盘。你要看 loss 趋势、eval loss、learning rate、训练速度和 checkpoint。真正可靠的判断要结合验证集、测试集和人工案例评估。
